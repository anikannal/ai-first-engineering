05

MVP Sprint

"Build something real, together, and ship it."

This Week's Goal

Your squad ships a live, deployed full-stack web application on Friday — demoed to a real external audience. This is the culmination of Phase 1. Everything you built in Weeks 1–4 was preparation for this.

What you'll learn this week

  • Run a real sprint: planning, standups, execution, retro
  • Scope an MVP — deciding what's in and what's out
  • Collaborate as an engineering team with PRs and code review
  • Use the AI Coach Sprint Assistant for product decomposition
  • Demo a product to an external audience

Monday — Product Discovery + Sprint Planning

Morning · 2 hrs

Product Discovery

Your squad aligns on an MVP idea. It must be: - A **full-stack web app** (frontend + backend + database) - Solving a **real, specific problem** for a real, specific type of user - **Demoable in 3 minutes** - **Achievable in one week** (this is the hard constraint — most squads overscope on day one) Use the Sprint Assistant to sharpen your idea: AI Coach · Sprint Assistant Draft your one-paragraph product brief, define your target user, and describe what "done" looks like for the MVP. The Sprint Assistant will challenge scope creep in real-time.
Afternoon · 2 hrs

Sprint Planning

Break the MVP into tasks. Each task must have: - A clear description - An owner - A definition of done - An **AI-assistance plan** — what will you prompt the AI to do? What will you do yourself? Every squad presents their plan to a human coach for a 20-minute sanity check. The coach's job is to challenge scope and surface risks — take the pushback seriously.

Tuesday–Thursday — Build Sprint

The rules this week: - All code goes through PRs — no direct commits to main - Every PR requires at least one squad review before merging - The AI Coach Code Review Agent reviews every PR before humans do - Daily standups at the start of each day — 15 minutes, async-friendly

AI Coach · Code Review Agent Every PR gets reviewed by the Code Review Agent first. It checks for correctness, security issues, missing error handling, and — importantly — flags AI-generated patterns that haven't been properly validated.

AI Coach · Course Coordinator The Course Coordinator tracks task completion daily and will flag your squad if you're falling behind. Don't ignore these nudges.

Wednesday mid-sprint check-in

Each squad presents current status to a human coach: what's done, what's at risk, what needs to be cut. Be honest. A realistic scope adjustment on Wednesday is better than a missed demo on Friday.

Friday — MVP Demo Day

Demo Day

External Audience · 5 min per squad

Each squad gets 5 minutes: - **3 minutes:** Live product demo — no slides, no video, no mockups. The real thing. - **2 minutes:** Q&A The audience will include faculty, industry contacts, and other students. Demo as if you're showing it to someone who might use it.
Assessment

Code Walkthrough · 10 min · 1:1 with Coach

After Demo Day (or the following Monday), you'll have a 10-minute 1:1 with your Engineering Coach. They'll show you 2–3 sections of your squad's codebase — including AI-generated sections — and ask you to explain them. **What the coach is looking for:** - Can you explain what this code does? - Can you identify something that could break? - Can you describe what the AI generated vs. what you wrote or changed? - Can you reason about how this fits into the rest of the system? No tricks. No gotchas. Just understanding.

Reflection

End-of-Phase Retrospective

AI Coach · Reflection Interviewer This week's reflection is longer — it's an end-of-phase retrospective: - What's the most important thing you learned in Phase 1? - What's the biggest gap between how you thought AI coding tools worked at the start vs. now? - What will you do differently in Phase 2?
